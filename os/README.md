# Nova 26H2

Nova 26H2 is a small BIOS-bootable x86-64 OS experiment. It reuses the Nova identity and high-resolution desktop direction of the `Try 1\os` project, while replacing its 32-bit protected-mode kernel with a native 64-bit freestanding C++ kernel.

## Build

From the workspace root, run:

```powershell
.\os\build.bat
```

The build uses the Dev-C++ MinGW-w64 compiler (`-m64`), the bundled NASM assembler, and Python 3 to embed the Chinese glyphs and ASC48 English glyphs used by the desktop and menu. It produces `os\build\nova-os-26h2.img` and the BIOS-bootable `os\build\nova-os-26h2.iso` so that an older running QEMU instance can keep using the previous disk image. The ISO contains the raw boot image as an El Torito no-emulation image and preloads its BIOS boot sectors; because the kernel currently reads its wallpaper through ATA PIO, an ISO boot falls back to a solid desktop background when no readable ATA hard disk provides the image. If Dev-C++ is installed elsewhere, set `DEVCPP_HOME` to its installation directory before building.

Source images are kept under the workspace-root `image` folder: wallpaper, logo, mouse pointer, and `image\icons\file.png` / `folder.png` for file-manager items. The build converts them into embedded kernel assets; generated headers and test screenshots in `os\build` are outputs, not source images.

Desktop application icons render at 64x64 pixels. The file manager has a path bar and a separate toolbar row with a built-in copy icon; no `image\tool` button assets are required yet. Select an item and click Copy, switch to A:, then right-click the destination and choose Paste. Copy supports files and nested folders from readable FAT12/16/32 volumes to the writable FAT16 A: data disk; B: remains read-only. Copies use each item's FAT 8.3 short name, do not overwrite existing entries, and are limited to 128 source entries per directory and 16 levels; the target directory must also have free entries. A failed folder copy may leave a partially copied destination folder. Right-clicking the desktop or file-manager window opens a rounded context menu. New creates an empty 8.3-named file or folder on A: (the desktop uses the A: root; the file manager uses its current A: directory); creation is disabled on B:. The current disk driver uses legacy IDE/ATA PIO and does not detect VMware SCSI controllers. NTFS is not implemented.

The BIOS loader requests a VBE 32-bit RGB linear framebuffer, uses the QEMU/Bochs VBE extension for 1920x1080 when available, and otherwise selects the largest compatible BIOS-listed 32-bit RGB mode up to 1920x1080. It builds identity-mapped 2 MiB page tables for the first 4 GiB and enters x86-64 long mode. The BIOS loads up to 256 kernel sectors from the boot disk; ISO boot preloads these sectors from its El Torito image. The desktop wallpaper is generated from `image\Wallpaper\img0.png` as a native 1920x1080 RGB565 image (4,147,200 bytes) at LBA 265; the kernel reads it into RAM through ATA PIO after entering long mode. The build assembles the five ZEX applications in `RUN\ZEX`, validates their version-2 headers, and embeds them in the kernel image, so runtime does not depend on a host `Z:` drive. Each ZEX application is loaded into its own memory slot and can keep its window open while another app is launched; the apps are cooperatively nested rather than preemptively scheduled. The window manager cascades open windows, restores the caller when a nested window closes, and keeps one instance of each bundled app. The taskbar shows only open app windows; clicking an existing app icon returns to that window. All bundled windows can be closed by clicking the title-bar × button or pressing Alt+F4; the desktop and mouse cursor are redrawn when the program exits. The file-manager ZEX browses FAT12/16/32 volumes using ATA PIO, including a persistent 32 MiB `os\build\nova-data.img` volume and the host folder `NovaShare` exposed by QEMU. The data image is created only when absent and is preserved by subsequent builds. The Nova data disk is located by its `NOVA DATA` FAT16 label across all four legacy IDE positions, while B: remains the QEMU shared folder; the file manager opens B: by default when the shared folder is mounted, otherwise it falls back to A:. Files placed in `NovaShare` appear on B:. The redesigned file manager has an A:/B: sidebar, a path bar, and an icon grid; clicking a volume remounts and reloads it, and the Refresh button or F5 rereads the current volume from its root. QEMU's FAT-folder backend snapshots the host folder when QEMU starts, so host-side changes made afterward are not visible through F5; close and restart QEMU after adding, removing, or changing files in `NovaShare`. The raw boot image is not browsable as a FAT system volume, and other host drive letters such as `X:\` are not automatically enumerated. File-manager navigation supports directory selection, Enter, Backspace, Tab volume switching, arrow-key and PageUp/PageDown scrolling (up to 128 entries), and Alt+F4. File creation on A: supports empty files and directories with ASCII FAT 8.3 names; B: remains read-only. The other bundled ZEX files remain window prototypes and do not yet implement their advertised full functionality. The full-HD mode reduces software-rendering and framebuffer-copy work. Desktop and loading frames are drawn to a back buffer before being presented, preventing partially rendered screen transitions. The build downsamples the source PNG into a 192x192 antialiased logo mask and embeds it with run-length encoding. Replace that PNG to change the default wallpaper; other source wallpapers can remain in the same folder. The desktop renders 64x64 antialiased app icons, while taskbar app icons are created only for apps with open windows. The software mouse pointer uses the antialiased image in `image\mouse.png` at 14x22 pixels (about 60% of its previous dimensions) and retains one-pixel movement precision. The startup screen contains only the Nova logo and a progress bar; shutdown displays the logo, “正在关机”, and an animated progress bar before briefly going black and requesting QEMU debug exit or ACPI S5. ASCII text uses coverage-based antialiasing to retain detail when scaled, and desktop icon labels are centered beneath their 64x64-pixel icons. Back-buffer drawing uses normal memory writes, and each row is copied to the framebuffer with `REP MOVSD` for faster full-screen presentation. The kernel is deliberately freestanding and does not depend on a hosted C++ runtime.

## Run

```powershell
.\os\run.bat
```

This builds the image and launches it in the bundled QEMU standard VGA device with a persistent data disk and the host folder `NovaShare` attached. Put files in `NovaShare` before launching to browse them in Nova; changes to that host folder made while QEMU is running require restarting QEMU to appear. No sample files are added. A Nova loading screen appears before the 1920x1080 desktop. The desktop displays a software mouse pointer in the center of the screen. The desktop, taskbar, and start menu use Chinese labels. Press the **Windows key** or click the Nova button at the bottom left to open or close the start menu. The menu lists all five apps; use **Up/Down** and **Enter**, or click an app to launch it. Multiple app windows can remain open together; the taskbar contains only apps with open windows, and selecting a running app returns to it. Each bundled app can have one open window at a time. The menu also provides restart and shutdown, and **Esc** closes it. Selecting **关机** powers off the guest and exits QEMU.

## Image layout

| Disk sectors | Contents |
| --- | --- |
| 0 | BIOS boot sector |
| 1-8 | Real-mode VBE and x86-64 loader |
| 9-264 | 64-bit kernel image (up to 256 sectors) |
| 265-1257 | 672x378 RGB565 Nova wallpaper |
